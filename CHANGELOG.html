0.2.2

  • LSP4IJ is now an optional dependency. The plugin used to refuse to install on an IDE build that LSP4IJ had not been released for yet, which is every new EAP for a while (reported by the Marketplace verifier on 2026.3 EAP). Highlighting, run configurations and the Saffron tool window need nothing from LSP4IJ and now work without it; completion, go-to-definition, hover and diagnostics switch on when LSP4IJ is installed. A one-time notification says so when it is missing.
  • The Proposals tab shows what a proposal changes: selecting one loads saffron diff under the narrative, so you approve the action list, not only the agent's account of it. Needs saffron-ai 0.6.1 or later.
  • Accept Selected with nothing ticked used to accept every proposal: blank paths mean --all to the runner. It now does nothing and says so, and bulk acceptance stays its own action.
  • An Orphans tab: caches and pending proposals whose scenario no longer exists, grouped and explained (the scenario is gone from the file, or the file itself is gone). Double-click opens the recording; Remove All runs saffron prune --yes after a confirmation. prune is also a run configuration command, where listing is the default and deleting is opt-in. Needs the saffron-ai release that added saffron prune.
  • The Proposals tab could show an old diff beside a new narrative. Diffs were cached by file name, and a new run overwrites a proposal under the same name, so Accept could promote something the reviewer never read. Every refresh now invalidates the diffs, a diff that finishes loading after a refresh is discarded, and the cache is only touched on the UI thread.
  • A path with a space stays one path. features/order checkout.saffron was split into two arguments, including for right-clicked and ticked files. Paths are now parsed like a command line (quotes keep a path whole), and whatever the plugin writes itself is quoted to match.

0.2.1

  • The Saffron tool window gains four tabs next to Files. Proposals: tick proposals, read the narrative, proof-replay verdict and cost, then Accept Selected, Reject Selected or Accept All. Tags: every @tag with its scenario count; tick and Run Tagged. Health: vocabulary counts, divergent steps, near-duplicate wordings, the effective config with one click to the file. Dashboard: the HTML report embedded in the IDE, reloaded after each run. The tabs read saffron status --json (saffron-ai 0.5.4 or later).
  • Run configurations: accept and reject take proposal files (blank means all).
  • Verifier clean on 2026.3.

0.2.0

  • Saffron run configurations: Run/Debug Configurations → Add New Configuration → Saffron. Choose run (files or folders, tags, replay-only, headed, re-record, extra arguments), report or accept. Output goes to the Run tool window; configurations can be stored as project files and shared.
  • Right-click to run: a .saffron file (project view or editor) or a folder holding them gets a "Run" entry, and the configuration it creates stays in the run widget.
  • Saffron tool window (right side, shown in Saffron projects): every feature file with its scenario count, search, tick files and Run Selected, Run All, Open Report, Accept All Proposals, plus the last run's totals and the number of proposals pending review. Double-click opens a file.
  • Runs use the project's own saffron-ai install (npx as a fallback) with the login shell's environment, so Node from nvm or Homebrew is found when the IDE was started from the Dock.
  • Go-to-definition and hover on {env:VAR} tokens open the variable in .env or .env.example (served by saffron-ai 0.5.2 or later).

0.1.2

  • Dark-theme file icon.

0.1.0

  • Initial release: .saffron file type and syntax highlighting (bundled TextMate grammar).
  • Language server integration via LSP4IJ: completion with recorded/divergent/unrecorded badges, StepSet completion, go-to-definition, hover, diagnostics. For .saffron and .feature files.
